## 一、文档概览

### 1. 接口简介

消息中心为 PA 内长耗时任务进度与各类通知的统一入口，支持消息列表、未读统计、已读标记、批量删除、进行中任务列表与计数等能力。  
消息中心不采用独立服务与长连接，系统级通知通过推送厂商（国内友盟 / 海外 Firebase）下发，App 内消息中心通过 REST 接口拉取。

### 2. 接口列表

| 序号 | 接口名称 | 接口地址 | 请求方式 | 调用方 |
|------|----------|----------|----------|--------|
| 1 | 消息列表 | /omniasst-management/api/v0/message-center/messages | GET | 客户端 |
| 2 | 未读消息数 | /omniasst-management/api/v0/message-center/messages/unread-count | GET | 客户端 |
| 3 | 单条消息标记已读 | /omniasst-management/api/v0/message-center/messages/{messageId}/read | POST | 客户端 |
| 4 | 批量消息标记已读 | /omniasst-management/api/v0/message-center/messages/read | POST | 客户端 |
| 5 | **清空所有消息** | /omniasst-management/api/v0/message-center/messages/clear | POST | 客户端 |
| 6 | **进行中任务列表（分页）** | /omniasst-management/api/v0/message-center/tasks/in-progress | GET | 客户端 |
| 7 | 进行中任务数量 | /omniasst-management/api/v0/message-center/tasks/in-progress/count | GET | 客户端 |
| 8 | 创建消息 | /omniasst-management/api/v0/message-center/messages/create | POST | 内部 |
| 9 | 创建进程任务 | /omniasst-management/api/v0/message-center/tasks/create | POST | 内部 |
| 10 | 完成进程任务 | /omniasst-management/api/v0/message-center/tasks/{taskId}/complete | POST | 内部 |
| 11 | **FCM 推送测试（调试）** | /omniasst-management/api/v0/debug/fcm-push | POST | 调试 |

## 二、客户端接口

### 1. 消息列表

### 1. 接口简介

分页查询当前用户的消息列表，按 `createdAt` 倒序返回。

### 2. 请求说明

| 名称 | 内容 |
|------|------|
| 接口地址 | /omniasst-management/api/v0/message-center/messages |
| 请求方式 | GET |
| Content-Type | application/json |

### 3. 请求参数

#### 3.1 Header 参数

| 参数 | 可选/必选 | 类型 | 说明 |
|------|-----------|------|------|
| X-User-Id | 必选 | String | 用户 ID |

#### 3.2 Query 参数

| 参数 | 可选/必选 | 类型 | 说明 |
|------|-----------|------|------|
| pageId | 可选 | Long | 当前页号，默认 1 |
| pageSize | 可选 | Long | 页面大小，默认 20 |

#### 3.3 Body 参数

无

### 4. 返回参数

| 参数 | 是否必返回 | 类型 | 说明 |
|------|------------|------|------|
| resCode | 是 | String | 状态码，成功为 `200` |
| resMessage | 是 | String | 状态描述，成功为 `success` |
| resContent.pageId | 是 | Long | 当前页号 |
| resContent.pageSize | 是 | Long | 每页条数 |
| resContent.totalCount | 是 | Long | 总条数 |
| resContent.content[].messageId | 是 | String | 消息 ID |
| resContent.content[].type | 是 | String | 消息类型：`meeting` / `translation` / `system` |
| resContent.content[].title | 是 | String | 消息标题 |
| resContent.content[].body | 否 | String | 消息正文/摘要 |
| resContent.content[].relatedId | 否 | String | 关联业务 ID |
| resContent.content[].relatedTitle | 否 | String | 关联业务标题 |
| resContent.content[].landingPage | 否 | String | 跳转路径 |
| resContent.content[].createdAt | 是 | String | 创建时间 |
| resContent.content[].readAt | 否 | String | 已读时间；为 `null` 表示未读 |

### 5. 请求&返回完整示例

#### 5.1 请求示例

```bash
curl -X GET "http://host:port/omniasst-management/api/v0/message-center/messages?pageId=1&pageSize=20" \
  -H "X-User-Id: user123"
```

#### 5.2 返回示例（成功）

```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": {
    "pageId": 1,
    "pageSize": 20,
    "totalCount": 5,
    "content": [
      {
        "messageId": "MSG1900000000000001",
        "type": "meeting",
        "title": "会议纪要已生成",
        "body": "项目周会纪要已完成",
        "relatedId": "minute_123",
        "relatedTitle": "项目周会 2026-03-11",
        "landingPage": "/meeting/minute/minute_123",
        "createdAt": "2026-03-11 10:30:00",
        "readAt": null
      }
    ]
  }
}
```

#### 5.3 返回示例（失败）

```json
{
  "resCode": "GENERAL_ERROR",
  "resMessage": "系统异常"
}
```

## 六、业务流程说明

### 1. 典型调用流程

1. 任务开始：业务模块调用 `POST /tasks/create`，进程列表出现新条目，角标 +1。  
2. 任务完成：业务模块调用 `POST /tasks/{taskId}/complete` + `POST /messages/create`，进程列表移除该条目（角标 -1），消息列表新增一条（未读 +1）。  
3. 用户进入消息中心：客户端调用 `GET /messages` + `GET /messages/unread-count` + `GET /tasks/in-progress` + `GET /tasks/in-progress/count`。  
4. 用户点击消息跳转：客户端调用 `POST /messages/{messageId}/read`，对应消息标记已读。

### 2. 未读数统计规则

- 未读数 = 该用户下 `read_at IS NULL` 的消息条数。  
- 进程任务不参与未读统计。  
- 进入消息中心不自动全部标已读，仅用户点击某条并跳转成功后该条标已读。

## 七、推送接口字段变更

### 1. POST /v0/push 新增字段

| 参数 | 可选/必选 | 类型 | 说明 |
|------|-----------|------|------|
| pushChannel | 可选 | String | 推送通道：`fcm` 走 Firebase，`umeng` 或不传走友盟 |
| silent | 可选 | Boolean | `true` 静默推送（不弹通知栏），`false` 系统通知（弹通知栏）；FCM 推送时若不传则根据 messageType 自动判断 |
| messageType | 可选 | String | `message`：新消息（静默）；`task`：任务变更（静默）；其他或不传：系统通知（弹通知栏） |
| relatedId | 可选 | String | 关联业务 ID（纪要 ID、翻译 ID、taskId 等），用于消息落库与 Firebase payload |
| relatedTitle | 可选 | String | 关联业务标题 |
| landingPage | 可选 | String | 跳转落地页路径（映射到 PushRequestDTO.route） |

### 2. FCM 推送拦截逻辑

当 `pushChannel=fcm` 时，management 的 `PushServiceImpl` 在 gRPC 推送前做拦截：

- **messageType=message**：先在 `pa_message` 表创建消息记录 → 查询该用户 `totalUnread` → 组装 Firebase data payload → 发送 data-only FCM 消息（静默）。
- **messageType=task**：通过 `relatedId`（即 taskId）查询任务详情 → 查询该用户进行中任务数 → 组装 Firebase data payload → 发送 data-only FCM 消息（静默）。
- **其他**：组装导航路由 payload → 发送 notification + data FCM 消息（系统通知，弹通知栏）。
