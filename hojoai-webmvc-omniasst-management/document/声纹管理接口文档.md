# 声纹管理接口文档

## 接口概览

管理服务提供声纹管理相关接口，包括声纹录入、查询、删除和匹配功能。

### 接口列表

1. **声纹录入** - `POST /omniasst-management/api/v0/voiceprint/register`
2. **声纹列表查询** - `POST /omniasst-management/api/v0/voiceprint/list`
3. **声纹删除** - `DELETE /omniasst-management/api/v0/voiceprint/{userId}`
4. **声纹匹配** - `POST /omniasst-management/api/v0/voiceprint/match`
5. **声纹展示名更新（仅改库字段）** - `POST /omniasst-management/api/v0/voiceprint/display-name`
6. **音色同步为声纹（会议 prepare 配套）** - `POST /omniasst-management/api/v1/meeting/voiceprint/register/copy-voice`

---

## 接口详情

### 1. 声纹录入

**接口路径**: `POST /omniasst-management/api/v0/voiceprint/register`

**请求方式**: POST

**Content-Type**: `multipart/form-data`

**请求参数** (FormData):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户ID |
| userName | String | 是 | 用户名 |
| audioFile | File | 是 | WAV格式音频文件（最大10MB） |

**响应格式**:

成功响应:
```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": "声纹录入成功"
}
```

错误响应:
- 参数错误：`resCode: "ILLEGAL_ARGUMENT"`, `resMessage: "用户ID不能为空"` 等
- 录入失败：`resCode: "GENERAL_ERROR"`, `resMessage: "声纹录入失败: {错误信息}"`

**处理逻辑**:
1. 验证请求参数（userId、userName、audioFile）
2. 调用语音服务的 `/v1/voiceprint/recognize/file` 接口获取声纹向量
3. 验证声纹向量是否有效（非空、维度正确）
4. 调用 `VoiceprintVectorService.saveUserVoiceprint` 保存声纹向量到PostgreSQL数据库
5. 返回成功响应

**数据库操作**:
- 表名：`user_voiceprints`
- 如果用户ID已存在，会更新该用户的声纹向量（ON CONFLICT处理）
- 声纹向量存储为PostgreSQL的vector类型（192维）

**请求示例**:
```bash
curl -X POST "http://host:port/omniasst-management/api/v0/voiceprint/register" \
  -F "userId=user123" \
  -F "userName=张三" \
  -F "audioFile=@/path/to/audio.wav"
```

### 2. 声纹列表查询

**接口路径**: `POST /omniasst-management/api/v0/voiceprint/list`

**请求方式**: POST

**Content-Type**: `application/json`

**请求参数** (JSON):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userName | String | 否 | 用户名（支持模糊查询） |
| page | Integer | 否 | 页码，默认1 |
| pageSize | Integer | 否 | 每页数量，默认20 |

**请求示例**:
```json
{
  "userName": "张三",
  "page": 1,
  "pageSize": 20
}
```

**响应格式**:

```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": {
    "list": [
      {
        "userId": "user123",
        "userName": "张三",
        "createdAt": "2025-01-01 10:00:00",
        "updatedAt": "2025-01-01 10:00:00"
      }
    ],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}
```

**响应字段说明**:
- `list`: 声纹用户信息列表
- `total`: 总记录数
- `page`: 当前页码
- `pageSize`: 每页数量

**处理逻辑**:
1. 解析请求参数，设置默认值（page=1, pageSize=20）
2. 调用 `VoiceprintVectorService.queryUserVoiceprints` 查询数据库
3. 如果提供了userName，使用LIKE模糊查询
4. 按updatedAt降序排序
5. 返回分页结果

**数据库查询**:
- 表名：`user_voiceprints`
- 支持按用户名模糊查询
- 分页查询，按更新时间降序排序

### 3. 声纹删除

**接口路径**: `DELETE /omniasst-management/api/v0/voiceprint/{userId}`

**请求方式**: DELETE

**路径参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户ID |

**响应格式**:

成功响应:
```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": "删除成功"
}
```

错误响应:
- 参数错误：`resCode: "ILLEGAL_ARGUMENT"`, `resMessage: "用户ID不能为空"`
- 用户不存在：`resCode: "ILLEGAL_ARGUMENT"`, `resMessage: "用户声纹不存在"`
- 删除失败：`resCode: "GENERAL_ERROR"`, `resMessage: "删除失败: {错误信息}"`

**处理逻辑**:
1. 验证userId参数
2. 调用 `VoiceprintVectorService.deleteUserVoiceprint` 删除数据库记录
3. 如果删除行数为0，返回"用户声纹不存在"错误
4. 返回成功响应

**数据库操作**:
- 表名：`user_voiceprints`
- 根据userId删除记录

**请求示例**:
```bash
curl -X DELETE "http://host:port/omniasst-management/api/v0/voiceprint/user123"
```

### 4. 声纹匹配（已存在）

**接口路径**: `POST /omniasst-management/api/v0/voiceprint/match`

**请求方式**: POST

**Content-Type**: `application/json`

**请求参数** (JSON):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| voiceprint | double[] | 是 | 声纹向量数组 |
| threshold | Double | 否 | 相似度阈值，默认0.85 |

**响应格式**:

```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": {
    "userId": "user123",
    "userName": "张三",
    "avatar": "avatar_url"
  }
}
```

**处理逻辑**:
1. 验证请求参数
2. 调用 `VoiceprintVectorService.matchUserVoiceprint` 进行匹配
3. 使用PostgreSQL的向量相似度计算（<=>操作符）
4. 返回匹配度最高的用户信息（如果相似度>=阈值）

### 5. 声纹展示名更新

在不重新采集音频、不修改声纹向量的前提下，仅更新 PostgreSQL 表 `user_voiceprints` 中的展示字段 **`user_name`**。供会议侧「仅修改昵称」等 BFF 场景调用；与 **`POST /v0/voice/save`**（音色资料中的昵称）配合使用时，由调用方保证业务语义一致。

**接口路径**: `POST /omniasst-management/api/v0/voiceprint/display-name`

**请求方式**: POST

**Content-Type**: `application/json`

**请求参数** (JSON):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户 ID；兼容 JSON 字段名 `user_id` |
| userName | String | 否 | 展示名，写入 `user_voiceprints.user_name`；不传或空串表示清空；兼容 `user_name` |

**响应格式**:

成功响应（`resContent` 为提示文案，以实际实现为准）:

```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": "更新成功"
}
```

错误响应（示例）:

- 用户 ID 为空：`resMessage` 含「用户ID不能为空」等
- 不存在该用户的声纹行：`resMessage` 含 **「用户声纹不存在」**（`UPDATE` 影响行数为 0）
- 其它异常：`resMessage` 含「更新失败」及原因

**处理逻辑**:

1. 校验 `userId` 非空  
2. 执行 `UPDATE user_voiceprints SET user_name = ?, updated_at = ... WHERE user_id = ?`  
3. 影响行数为 0 时返回「用户声纹不存在」

**请求示例**:

```bash
curl -X POST "http://host:port/omniasst-management/api/v0/voiceprint/display-name" \
  -H "Content-Type: application/json" \
  -d "{\"userId\":\"user123\",\"userName\":\"新展示名\"}"
```

**说明**:

- 本接口**不**调用语音服务，**不**变更 `voiceprint` 向量。  
- 会议服务 `commit` 在 **`updateNicknameOnly=true`** 时会在 `voice/save` 之后调用本接口；若用户仅有音色资料、**尚未**存在 `user_voiceprints` 行，本接口会失败，会议侧可对「用户声纹不存在」类错误做降级处理（仅音色昵称已更新）。

### 6. 音色同步为声纹（copy-voice）

与 **`POST /omniasst-management/api/v1/meeting/voiceprint/register/prepare`** 配套使用：前端**仅传 `userId`**，由服务端根据 Redis 中暂存的原始音频或音色克隆暂存生成声纹向量并写入 `user_voiceprints`（存在则更新）。

**接口路径**: `POST /omniasst-management/api/v1/meeting/voiceprint/register/copy-voice`

**请求方式**: POST

**Content-Type**: `application/json`

**请求参数** (JSON):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户 ID；兼容 JSON 字段名 `user_id` |

**请求示例**:

```json
{
  "userId": "user123"
}
```

**响应格式**:

成功响应（`resContent` 为提示文案，以实际实现为准）:

```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": "声纹同步成功"
}
```

错误响应（示例）:

- 参数错误：`resMessage` 含「用户ID不能为空」等
- 业务条件不满足：`resMessage` 含「用户音色不存在」「音色档案缺少 voiceId」「无法生成声纹：未找到会议 prepare 暂存音频…」等
- 声纹识别或落库失败：`resMessage` 含「声纹同步失败: …」或「声纹识别失败：…」等

**处理逻辑**（概要）:

1. 校验 `userId` 非空。  
2. 查询 MySQL（或当前配置的数据源）表 **`user_voice_profiles`**：须存在该用户音色，且 **`voice_id` 非空**。  
3. **优先**：若 Redis 中存在本会话 **`prepare` 阶段写入的原始音频**（与当前档案中的 `voice_id` 一致），则取出音频调用语音服务 **`POST /omniasst-voice/v1/voiceprint/recognize/file`** 得到向量，写入/更新 `user_voiceprints`；成功后删除该音频暂存键。  
4. **否则**：若存在与当前 `voice_id` 一致的 **音色克隆暂存**（`/v0/voice/clone` 成功后写入的 Redis 数据），则直接使用其中的向量写入 `user_voiceprints`；成功后删除克隆暂存键。  
5. 若以上均不可用，返回明确错误，提示先完成会议 **`prepare`** 或音色克隆，并在有效期内调用。

**展示名（`user_voiceprints.user_name`）规则**:

- 优先使用音色档案中的 **`nickname`**，其次 **`voice_name`**，否则回退为 **`userId`**。

**与 prepare / commit 的关系**:

| 说明 | 内容 |
|------|------|
| 调用顺序 | 须先在同一管理实例上成功调用 **`prepare`**（multipart 上传录音），且建议在 **`prepare` 时 `needSave=true`**，保证 `user_voice_profiles` 已落库且 `voice_id` 与暂存一致。 |
| 有效期 | 会议 **`prepare` 写入的 JSON 缓存、原始音频暂存** 与 **克隆暂存** 均为 **约 30 分钟 TTL**（以服务端配置为准）。 |
| 与 `commit` | 调用 **`commit`** 会清除会议 prepare 的 JSON 缓存及原始音频暂存。若先 **`commit`** 再调本接口，则**无法**再走「prepare 暂存音频」分支；是否仍可走「克隆暂存」取决于是否尚未被消费。 |
| 网关 | 若网关将 `omniasst-meeting` 前缀转发到本服务，路径需与部署的 **context-path**（默认含 `/omniasst-management/api`）一致。 |

**请求示例（curl）**:

```bash
curl -X POST "http://host:port/omniasst-management/api/v1/meeting/voiceprint/register/copy-voice" \
  -H "Content-Type: application/json" \
  -d "{\"userId\":\"user123\"}"
```

**数据库操作**:

- 表名：`user_voiceprints`  
- 与 **`POST /v0/voiceprint/register`** 类似：按 `user_id` **插入或更新** 声纹向量（`ON CONFLICT` 语义以实际 DAO 为准）。

## 通用说明

### 数据库表结构

#### 正式表：user_voiceprints

**表名**: `user_voiceprints`

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGSERIAL | 主键 |
| user_id | VARCHAR(255) | 用户ID（唯一） |
| user_name | VARCHAR(255) | 用户名 |
| voiceprint | vector(192) | 声纹向量（192维） |
| avatar | VARCHAR(255) | 头像URL（可选） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 声纹向量

- **维度**: 192维
- **存储格式**: PostgreSQL vector类型
- **相似度计算**: 使用PostgreSQL的向量距离操作符（<=>）

### 错误处理

所有接口在发生错误时会返回相应的错误信息：
- `ILLEGAL_ARGUMENT`: 参数错误（如参数为空、用户不存在）
- `GENERAL_ERROR`: 通用错误（如服务调用失败、数据库操作失败）

### 日志记录

关键操作会记录日志：
- 声纹录入：记录userId、userName、向量维度
- 声纹查询：记录查询参数和结果数量
- 声纹删除：记录userId和删除行数
- 服务调用：记录调用语音服务的请求和响应

## 服务依赖

### 语音服务接口

管理服务依赖语音服务的以下接口：
- `POST /omniasst-voice/v1/voiceprint/recognize/file` - 声纹识别（文件上传）

### 数据库

- **数据库类型**: PostgreSQL
- **连接配置**: `spring.datasource.postgresql.*`
- **JdbcTemplate**: `postgresqlJdbcTemplate`

---

## 注意事项

### 正式表相关
1. **声纹录入**会自动调用语音服务进行音频处理和声纹识别
2. **数据库操作**使用PostgreSQL的vector类型存储声纹向量
3. **相似度阈值**默认值为0.85，可在配置文件中修改（`voiceprint.similarity.threshold`）
4. **分页查询**默认每页20条记录
5. 如果用户ID已存在，**声纹录入**会更新该用户的声纹向量
