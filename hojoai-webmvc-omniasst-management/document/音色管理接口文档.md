# 音色管理接口文档

## 接口概览

管理服务提供音色克隆相关接口，支持多厂商音色克隆功能。

### 接口列表

1. **音色克隆** - `POST /omniasst-management/api/v0/voice/clone`
2. **获取用户音色信息** - `GET /omniasst-management/api/v0/voice/profile`
3. **删除用户音色** - `DELETE /omniasst-management/api/v0/voice/profile`
4. **保存用户音色资料** - `POST /omniasst-management/api/v0/voice/save`


## 接口详情

### 1. 音色克隆

**接口路径**: `POST /omniasst-management/api/v0/voice/clone`

**请求方式**: POST

**Content-Type**: `multipart/form-data`

**请求参数** (FormData):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户ID |
| voiceName | String | 否 | 音色名称 |
| provider | String | 是 | 厂商标识。可选值：hojo（恒聚） |
| file | File | 是 | PCM格式音频文件 |

**参数说明**:
- `provider`: 厂商标识，用于标识音色是由哪个厂商生成的。目前仅支持 `hojo`（恒聚），其他厂商暂不支持。**必填参数**
- `file`: 音频文件格式为PCM，16k采样率，16bit，单声道。建议至少5秒音频

**响应格式**:

成功响应:
```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": {
    "voiceId": "voice-1234567890123456789"
  }
}
```

错误响应:
- 参数错误：`resCode: "ILLEGAL_ARGUMENT"`, `resMessage: "暂不支持的厂商: xxx"` 等
- 克隆失败：`resCode: "GENERAL_ERROR"`, `resMessage: "音色复刻失败: {错误信息}"`

**处理逻辑**:
1. 验证请求参数（userId、file）
2. 验证厂商标识，目前仅支持 `hojo`
3. 调用语音服务的 `/v1/voice/clone` 接口进行音色克隆
4. 如果用户已有音色记录，先删除旧记录
5. 保存新的音色记录到数据库（包含userId、voiceId、voiceName、provider）
6. 返回克隆后的音色ID

**数据库操作**:
- 表名：`user_voice_profiles`
- 每个用户只能有一个音色（如果用户已有音色，会覆盖旧记录）
- 保存字段：`user_id`、`voice_id`、`voice_name`、`provider`、`created_at`、`updated_at`

**请求示例**:
```bash
curl -X POST "http://host:port/omniasst-management/api/v0/voice/clone" \
  -F "userId=user123" \
  -F "voiceName=我的音色" \
  -F "provider=hojo" \
  -F "file=@/path/to/audio.pcm"
```

**注意事项**:
1. 每个用户只能有一个音色，如果用户已有音色，新克隆的音色会覆盖旧记录
2. 目前仅支持 `hojo` 厂商，其他厂商会返回错误
3. 音频文件建议至少5秒，格式为PCM（16k采样率，16bit，单声道）
4. `provider` 参数必填，必须明确指定厂商

### 2. 获取用户音色信息

**接口路径**: `GET /omniasst-management/api/v0/voice/profile`

**请求方式**: GET

**请求参数** (Query):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户ID |

**响应格式**:

成功响应:
```json
{
  "resCode": "200",
  "resMessage": "Success",
  "resContent": {
    "id": 1,
    "userId": "user123",
    "voiceId": "voice_abc123",
    "voiceName": "我的音色",
    "provider": "hojo",
    "createdAt": "2025-01-07T10:30:00",
    "updatedAt": "2025-01-07T10:30:00"
  }
}
```

错误响应:
- 用户音色不存在：`resCode: "GENERAL_ERROR"`, `resMessage: "用户音色不存在"`
- 参数错误：`resCode: "ILLEGAL_ARGUMENT"`, `resMessage: "用户ID不能为空"`

**请求示例**:
```bash
curl -X GET "http://host:port/omniasst-management/api/v0/voice/profile?userId=user123"
```

### 3. 删除用户音色

**接口路径**: `DELETE /omniasst-management/api/v0/voice/profile`

**请求方式**: DELETE

**请求参数** (Query):

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户ID |

**响应格式**:

成功响应:
```json
{
  "resCode": "200",
  "resMessage": "Success",
  "resContent": "删除成功"
}
```

错误响应:
- 用户音色不存在：`resCode: "GENERAL_ERROR"`, `resMessage: "用户音色不存在"`
- 参数错误：`resCode: "ILLEGAL_ARGUMENT"`, `resMessage: "用户ID不能为空"`
- 删除失败：`resCode: "GENERAL_ERROR"`, `resMessage: "删除失败：{错误信息}"`

**请求示例**:
```bash
curl -X DELETE "http://host:port/omniasst-management/api/v0/voice/profile?userId=user123"
```

**注意事项**:
1. 删除操作不可恢复，请谨慎操作
2. 如果用户音色不存在，会返回错误信息

### 4. 保存用户音色资料

将用户与厂商下的音色资料写入表 `user_voice_profiles`（存在则按实现覆盖）。会议侧「仅修改昵称」、`commit` 常规流程中的音色落库等均可能调用本接口。

**接口路径**: `POST /omniasst-management/api/v0/voice/save`

**请求方式**: POST

**Content-Type**: `application/json`

**请求体**（字段与 `VoiceCloneRequest` 一致，蛇形命名亦兼容）:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | String | 是 | 用户 ID |
| voiceId | String | 是 | 音色 ID |
| provider | String | 是 | 厂商，如 `hojo`、`minimax` |
| voiceName | String | 否 | 音色展示名；可与业务上的「克隆名称」对齐 |
| nickname | String | 否 | 用户昵称；可与 `voiceName` 分别维护 |

**响应格式**:

成功：

```json
{
  "resCode": "200",
  "resMessage": "success",
  "resContent": "保存成功"
}
```

**请求示例**:

```bash
curl -X POST "http://host:port/omniasst-management/api/v0/voice/save" \
  -H "Content-Type: application/json" \
  -d "{\"userId\":\"user123\",\"voiceId\":\"voice_abc\",\"provider\":\"hojo\",\"voiceName\":\"我的音色\",\"nickname\":\"展示昵称\"}"
```

**说明**: 与《声纹管理接口文档》中 **`POST /v0/voiceprint/display-name`** 作用域不同：本接口维护 **`user_voice_profiles`**；声纹展示名维护 **`user_voiceprints.user_name`**。

## 厂商说明

### 支持的厂商

| 厂商代码 | 厂商名称 | 说明 |
|---------|---------|------|
| hojo | 恒聚 | 当前唯一支持的厂商 |

### 未来扩展

系统设计支持多厂商扩展，未来可以添加更多厂商支持：
- 阿里云（aliyun）
- 腾讯云（tencent）
- 其他厂商

添加新厂商时，需要在 `VoiceProviderEnum` 枚举中添加对应的厂商定义。

## 数据库表结构

**表名**: `user_voice_profiles`

**字段说明**:

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGSERIAL | 主键，自增 |
| user_id | VARCHAR(255) | 用户ID |
| voice_id | VARCHAR(255) | 音色ID（由音色克隆服务返回） |
| voice_name | VARCHAR(255) | 音色名称（可选） |
| nickname | VARCHAR(255) | 用户自定义昵称（可选，默认等同 voice_name） |
| provider | VARCHAR(50) | 厂商标识（如：hojo） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

**索引**:
- `idx_user_voice_profiles_user_id` - 用户ID索引
- `idx_user_voice_profiles_voice_id` - 音色ID索引
- `idx_user_voice_profiles_provider` - 厂商索引

**约束**:
- `UNIQUE(user_id, voice_id)` - 用户和音色的唯一约束
