# 会议场景 · 音色克隆 / 保存接口文档

## 1. 功能说明

会议服务提供 **BFF（Backend For Frontend）**，将前端请求转发至 **management** 的音色能力，与项目内其它接口保持 **同一套 `Response<T>`、同一 Context Path 前缀**（`/omniasst-meeting/v1/meeting/...`），避免前端直连 management 域名或多套鉴权方式。

| 接口 | 作用 | 转发至 management |
|------|------|-------------------|
| `clone` | 上传 WAV 音频，克隆音色，返回 `voiceId` | `POST /omniasst-management/api/v0/voice/clone`（`multipart/form-data`） |
| `save` | 将已克隆的 `voiceId` 正式入库（或按 management 语义落库） | `POST /omniasst-management/api/v0/voice/save`（`application/json`） |

**与「个人声纹注册」的关系：**

- 同一段录音若既要 **声纹** 又要 **音色**，需分别调用：
  - 声纹：`/v1/meeting/voiceprint/register/prepare` → `commit`（两阶段，见《个人声纹注册接口文档》）。
  - 音色：本文件的 `clone`（及按需 `save`）。
- 会议侧 **不** 将二者合并为单一接口；management 侧能力分离，由产品决定调用顺序（例如先 prepare/commit 声纹，再 clone；或并行，以实际业务为准）。

**依赖：**

- **Management 服务**（需注册到服务发现，供 LoadBalanced `RestTemplate` 解析；服务名见配置项）。

### 1.1 本次迭代可用接口（会议侧 BFF）

| 能力 | Method & Path | 说明 |
|------|---------------|------|
| 声音复刻（克隆） | `POST /omniasst-meeting/v1/meeting/voice/clone` | multipart，见下文 §4 |
| 音色保存 | `POST /omniasst-meeting/v1/meeting/voice/save` | JSON，见下文 §5 |
| 查询音色/声纹资料 | `GET /omniasst-meeting/v1/meeting/voice/profile` | Query：`userId`、可选 `provider`、`type`（0 或省略=声音 / 1=声纹） |
| 声纹复刻（注册） | `POST .../v1/meeting/voiceprint/register/prepare` → `.../commit` | 两阶段，见《个人声纹注册接口文档》 |

### 1.2 可选参数 `replicateType`（与前端约定）

用于标明「声音复刻」还是「声纹复刻」，**不传不影响原有逻辑**：

| 取值 | 含义 |
|------|------|
| `VOICE` | **声音复刻**（音色克隆） |
| `VOICEPRINT` | **声纹复刻**（声纹注册） |

**默认行为（与接口语义一致）：**

- **`/v1/meeting/voice/clone`、`/v1/meeting/voice/save`**：未传 `replicateType` 时视为 **`VOICE`**（声音复刻），与上线前行为一致。
- **JSON** **`/v1/meeting/voiceprint/register/prepare`**（及 **`copy-voice`**）：未传 `replicateType` 时视为 **`VOICEPRINT`**（声纹复刻）。**multipart** 同路径另用 Query/表单整数 **`type`**：**`0` 或省略=声音（默认）**，**`1`=声纹**，与 **`GET .../voice/profile`** 的 `type` 一致。**`/commit`** 不传 `replicateType` / `type`，流程由阶段一暂存决定。

**防误调：** 若在 **音色** 接口上传 **`VOICEPRINT`**，或在 **声纹** 接口上传 **`VOICE`**，会议侧会返回 **参数错误**（`IllegalArgumentException` 文案），提示改用正确路径。

## 3. 统一响应结构

与《个人声纹注册接口文档》及项目内其它接口一致，使用 `Response<T>`：

| 字段 | 类型 | 说明 |
|------|------|------|
| resCode | String | 成功多为 `OK`（以 `hojoai-common` 为准） |
| resMessage | String | 描述信息 |
| resContent | T | 业务数据 |

失败时可能抛出异常，HTTP 层可能为 **4xx/5xx** 及 Spring 默认错误体；联调时以服务端日志与网关返回为准。

## 4. 接口一：音色克隆 clone

### 4.1 描述

上传 **WAV** 格式音频，调用 management 克隆音色；成功时返回 `voiceId`（会议侧 `resContent` 使用驼峰字段名 `voiceId`，与 management 原始 JSON 中的 `voice_id` 对应）。

### 4.2 请求

| 项 | 值 |
|----|-----|
| Method | `POST` |
| Path | `/omniasst-meeting/v1/meeting/voice/clone` |
| Content-Type | `multipart/form-data` |

**Body（multipart 字段）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userId | String | 是 | 用户 ID |
| file | File | 是 | 音频文件，**WAV**；表单字段名固定为 **`file`** |
| voiceName | String | 否 | 音色名称；不传则转发时不带该字段 |
| needSave | Boolean | 否 | **未传或 `false`**：按 `false` 处理（不入库，仅克隆）；传 `true` 表示需要直接入库（与 management 文档一致） |
| provider | String | 否 | 厂商标识；**未传时会议侧默认 `hojo`** |
| replicateType | String | 否 | `VOICE`（默认，可省略）或 `VOICEPRINT`；传 `VOICEPRINT` 会报错并提示改用声纹接口，见 §1.2 |

### 4.3 响应

**成功时 `resContent`（JSON 对象）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| voiceId | String | 克隆得到的音色 ID，后续 `save` 使用 |

### 4.4 请求示例（curl）

```bash
curl -X POST "http://{host}:12007/omniasst-meeting/v1/meeting/voice/clone" \
  -F "userId=user123" \
  -F "voiceName=我的音色" \
  -F "needSave=false" \
  -F "provider=hojo" \
  -F "file=@/path/to/audio.wav"
```

### 4.5 说明

- 音频格式与 **management** 要求一致；**非 WAV 仅改后缀** 可能导致失败。  
- 若需「先克隆再让用户确认是否保存」，通常 `clone` 时传 **`needSave=false`**，用户确认后再调 **save**。

## 5. 接口二：音色保存 save

### 5.1 描述

在已拿到 `voiceId` 后，由前端决定是否调用，将音色信息按 management 约定落库（具体语义以 management 为准）。

### 5.2 请求

| 项 | 值 |
|----|-----|
| Method | `POST` |
| Path | `/omniasst-meeting/v1/meeting/voice/save` |
| Content-Type | `application/json` |

**Body（JSON）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userId | String | 是 | 用户 ID |
| voiceId | String | 是 | `clone` 返回的 `voiceId` |
| voiceName | String | 否 | 音色名称 |
| provider | String | 否 | 厂商标识；**未传时会议侧默认 `hojo`** |
| replicateType | String | 否 | `VOICE`（默认，可省略）；**仅会议侧识别**，不会原样转发给 management；误传 `VOICEPRINT` 会报错，见 §1.2 |

### 5.3 响应

**成功时：** `resCode` 为成功态，`resContent` 一般为 **字符串**（如 management 返回的「保存成功」等），与 management 原始响应一致。

### 5.4 请求示例（JSON）

```json
{
  "userId": "user123",
  "voiceName": "我的音色",
  "provider": "hojo",
  "voiceId": "voice-1234567890123456789"
}
```

## 7. 调用顺序示例

**仅克隆、不入库，再保存：**

```text
1. POST .../v1/meeting/voice/clone
   multipart: userId, file, needSave=false（或省略 needSave）
   → 保存 resContent.voiceId

2. POST .../v1/meeting/voice/save
   JSON: { "userId", "voiceId", ... }
```

**克隆时即入库（与 management 支持一致时）：**

```text
POST .../clone  multipart: needSave=true
→ 可能无需再调 save，以产品与管理端约定为准
```

## 9. 未包含在本服务的部分

- **音色列表 / 查询 / 删除** 等：需 management 提供对应 API 后，再决定是否做会议侧 BFF。  
- **声纹「昵称」**：属于声纹 `commit` 的 `nickname` 字段，与音色 `voiceName` 不是同一套接口，产品需区分展示与落库。  
- management 侧 **具体表结构、厂商扩展（minimax 等）** 以 management 文档为准。

以上由对应服务/前端补充。
