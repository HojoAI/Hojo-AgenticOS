# 会议场景全链路处理流程说明

## 一、流程概览

从建立WebSocket长连接到处理完成一段音频的全链路流程如下：

```
连接建立 → 下发meetingId → 接收音频数据 → Base64解码 → 累积缓冲区 → 
VAD检测 → ASR识别 → 音频段管理 → 段完成处理 → OSS追加 → 
声纹识别 → 向量匹配 → Redis发布 → 客户端响应
```

---

## 二、详细流程（结合代码方法）

### 阶段1：连接建立与初始化

#### 1.1 客户端建立WebSocket连接
- **连接路径**: `ws://host:port/omniasst-voice/meeting`
- **请求头**: `X-Device-Id: device123`

#### 1.2 服务端处理连接建立
**方法**: `afterConnectionEstablished(WebSocketSession session)`

**处理流程**:
```java
// 1. 注册心跳管理
heartbeatManager.registerSession(session, "MeetingWebSocketHandler");

// 2. 创建SessionState并生成meetingId
SessionState state = new SessionState();
state.meetingId = "meeting-" + snowflake.nextId();  // 雪花ID生成唯一会议ID
state.meetingStartTime = System.currentTimeMillis(); // 记录会议开始时间
state.recording = true;  // 标记为录制状态
sessionStates.put(sessionId, state);

// 3. 发送meetingId给客户端
MeetingIdResponse response = new MeetingIdResponse();
response.setMeetingId(state.meetingId);
response.setTimestamp(state.meetingStartTime);
IMessageCustom.sendMessageCustom(session, IMessageEvent.BACK_MEETING_ID, response);
```

**关键数据**:
- `meetingId`: 唯一会议标识（格式：`meeting-{雪花ID}`）
- `meetingStartTime`: 会议开始时间戳（用于计算时间轴）

**客户端收到消息**:
```json
{
  "event": "BACK_MEETING_ID",
  "payload": {
    "pdata": {
      "meetingId": "meeting-1234567890123456789",
      "timestamp": 1704067200000
    }
  }
}
```

#### 2.2 服务端接收并解析消息
**方法**: `handleMessage(WebSocketSession session, WebSocketMessage<?> message)`

```java
// 更新心跳时间
heartbeatManager.updateLastActiveTime(session);

// 判断消息类型
if (message instanceof TextMessage) {
    handleTextMessage(session, (TextMessage) message);  // Base64音频数据
} else if (message instanceof BinaryMessage) {
    handleBinaryMessage(session, (BinaryMessage) message);  // 二进制音频（兼容）
}
```

**方法**: `handleTextMessage(WebSocketSession session, TextMessage message)`

```java
// 1. 解析消息
IMessage<?> iMessage = JacksonUtil.json2Bean(message.getPayload(), IMessage.class);
String eventType = iMessage.getEventType();

// 2. 判断事件类型
if (IMessageEvent.REQ_MEETING_AUDIO_DATA.getEventType().equals(eventType)) {
    handleAudioData(session, message.getPayload(), state);
}
```

**方法**: `handleAudioData(WebSocketSession session, String message, SessionState state)`

```java
// 1. 解析请求
MeetingAudioDataRequest request = IMessageCustom.parseBusinessRequest(message, MeetingAudioDataRequest.class);

// 2. Base64解码音频数据
byte[] audioBytes = java.util.Base64.getDecoder().decode(request.getAudioData());

// 3. 处理音频数据
processAudioData(session, state, audioBytes);
```

### 阶段3：音频数据累积与VAD检测

#### 3.1 累积音频数据到缓冲区
**方法**: `processAudioData(WebSocketSession session, SessionState state, byte[] audioData)`

```java
// 1. 累积到缓冲区（每个session独立的缓冲区）
ByteArrayOutputStream buffer = sessionBuffers.computeIfAbsent(session.getId(), k -> new ByteArrayOutputStream());
buffer.write(audioData);

// 2. 当累积到CHUNK_SIZE（10240字节，约320ms的音频）时开始处理
if (buffer.size() >= CHUNK_SIZE) {
    byte[] completeData = buffer.toByteArray();
    buffer.reset();  // 清空缓冲区，准备下一批
    // 继续处理...
}
```

**说明**:
- `CHUNK_SIZE = 320 * 16 * 2 = 10240` 字节
- 对应320ms的PCM音频（16000采样率，16bit，单声道）

#### 3.2 VAD检测（语音活动检测）
**目的**: 判断音频中是否包含有效语音

```java
// 1. 获取或创建VID（VAD会话ID）
String vid = vidMap.computeIfAbsent(session.getId(), k -> String.valueOf(snowflake.nextId()));

// 2. 构建VAD请求
VADRequest vadRequest = makeVadRequest(java.util.Base64.getEncoder().encodeToString(completeData));
// 参数：packageData（Base64音频）、packageSize、vadEnd=60

// 3. 调用VAD API
VADResponse vadResponse = vadAPI.vad(vadRequest);

// 4. 计算VAD评分
int vadScore = evaluate(vadResponse);  // 计算有效语音时长（毫秒）
```

**VAD评分机制**:
```java
// 维护最近3个包的VAD评分队列
Deque<Integer> vadScoreQueue = vadScoreMap.computeIfAbsent(vid, k -> new ArrayDeque<>());

// 如果VAD评分不为0（有有效语音）
if (vadScore != 0) {
    audioBuffer.addLast(completeData);      // 保存音频包
    vadScoreQueue.addLast(vadScore);        // 保存VAD评分
    
    // 保持队列大小不超过3
    if (audioBuffer.size() > VAD_QUEUE_SIZE) {
        audioBuffer.pollFirst();
        vadScoreQueue.pollFirst();
    }
    
    // 计算累计VAD评分
    int totalVadScore = vadScoreQueue.stream().mapToInt(Integer::intValue).sum();
    
    // 如果累计评分达到阈值（20包），开始ASR识别
    if (totalVadScore >= VAD_VALID_PACKAGE_THRESHOLD) {
        vadFlagMap.put(vid, false);  // 标记不再需要VAD检测
        // 开始ASR处理...
    }
}
```

**关键参数**:
- `VAD_VALID_PACKAGE_THRESHOLD = 20`（累计有效语音包数阈值）
- `VAD_QUEUE_SIZE = 3`（VAD评分队列大小）

### 阶段4：ASR识别

#### 4.1 初始化新音频段
**方法**: `startNewSegment(SessionState state)`

```java
// 当检测到有效语音，开始新的音频段
if (StringUtils.isBlank(state.asrVid)) {
    state.asrVid = String.valueOf(snowflake.nextId());  // ASR会话ID
    startNewSegment(state);  // 开始新段
}

// startNewSegment实现：
state.currentSegmentId = String.valueOf(snowflake.nextId());  // 段ID
state.currentSegmentStartOffset = state.totalValidAudioDuration;  // 段在总时间轴的起始位置
state.currentSegmentAudio.clear();  // 清空当前段音频包列表
state.fixedText = "";  // 清空已确认文本
state.tmpText = "";    // 清空临时文本

// 初始化OSS对象key（第一段时）
if (state.ossPcmObjectKey == null) {
    state.ossPcmObjectKey = "meeting/" + state.meetingId + "/audio.pcm";
}
```

#### 4.2 处理ASR识别
**方法**: `processAsr(byte[] audioData, SessionState state, WebSocketSession session)`

```java
// 1. 累积音频到当前段
state.currentSegmentAudio.add(audioData);  // 保存到当前段的音频包列表

// 2. 构建ASR请求
String audioBase64 = java.util.Base64.getEncoder().encodeToString(audioData);
ASRRequest asrRequest = makeAsrRequest(audioBase64, state.asrVid, state.asrPackageIndex);
// 参数：task="all", vid, packageIndex, packageSize, type="pcm", lang="all"

// 3. 调用ASR API
ASRResponse asrResponse = asrAPI.asr(asrRequest);

// 4. 更新ASR文本
updateAsrText(state, asrResponse);

// 5. 发送ASR文本响应给客户端
sendAsrTextResponse(session, state, asrResponse.getIsEnd());

// 6. 如果isEnd=1，表示一段音频结束
if (asrResponse.getIsEnd() == 1) {
    completeCurrentSegment(session, state);  // 完成当前段处理
}
```

#### 4.3 更新ASR文本
**方法**: `updateAsrText(SessionState state, ASRResponse asrResponse)`

```java
ASRResponse.ASRText textInfo = asrResponse.getText();

// 更新fixedText（已确认的文本）
if (StringUtils.isNotBlank(textInfo.getFixedText())) {
    state.fixedText = textInfo.getFixedText();
}

// 更新tmpText（临时文本）
if (StringUtils.isNotBlank(textInfo.getTmpText())) {
    state.tmpText = textInfo.getTmpText();
}

// isEnd=1时，tmpText会合并到fixedText
if (asrResponse.getIsEnd() == 1 && StringUtils.isNotBlank(textInfo.getTmpText())) {
    state.fixedText = state.fixedText + textInfo.getTmpText();
    state.tmpText = "";
}
```

#### 4.4 发送ASR文本响应
**方法**: `sendAsrTextResponse(WebSocketSession session, SessionState state, int isEnd)`

```java
MeetingAsrTextResponse response = new MeetingAsrTextResponse();
response.setFixedText(state.fixedText);  // 已确认文本（显示一种颜色）
response.setTmpText(state.tmpText);      // 临时文本（显示另一种颜色）
response.setIsEnd(isEnd);                // 是否结束（0=未结束，1=结束）
response.setSegmentId(state.currentSegmentId);  // 当前段ID
IMessageCustom.sendMessageCustom(session, IMessageEvent.BACK_MEETING_ASR_TEXT, response);
```

**客户端收到消息**:
```json
{
  "event": "BACK_MEETING_ASR_TEXT",
  "payload": {
    "pdata": {
      "fixedText": "你好，这是一段",
      "tmpText": "测试",
      "isEnd": 0,
      "segmentId": "seg-1234567890123456789",
      "segmentStartTime": "00:05"
    }
  }
}
```

### 阶段5：音频段完成处理

#### 5.1 完成当前段
**触发条件**: ASR返回 `isEnd = 1`

**方法**: `completeCurrentSegment(WebSocketSession session, SessionState state)`

```java
// 1. 合并当前段的所有音频包
byte[] segmentAudio = mergeAudioPackages(state.currentSegmentAudio);
// 将List<byte[]>合并成一个完整的byte[]数组

// 2. 计算段时长（毫秒）
long segmentDuration = (segmentAudio.length * 1000) / PCM_BYTES_PER_MS;
// PCM_BYTES_PER_MS = 16000 * 2 / 1000 = 32（每毫秒32字节）

// 3. 计算段在总时间轴的位置
long segmentStartOffset = state.totalValidAudioDuration;  // 段开始位置
long segmentEndOffset = state.totalValidAudioDuration + segmentDuration;  // 段结束位置

// 4. 追加音频到OSS
long ossStartPosition = state.ossCurrentPosition;  // OSS中的起始位置
state.ossCurrentPosition = ossUtil.appendObject(state.ossPcmObjectKey, segmentAudio, state.ossCurrentPosition);
long ossEndPosition = state.ossCurrentPosition;  // OSS中的结束位置

// 5. 声纹识别
String speakerId = performVoiceprintRecognition(state.meetingId, segmentAudio);

// 6. 记录段信息
AudioSegmentInfo segmentInfo = new AudioSegmentInfo();
segmentInfo.segmentId = state.currentSegmentId;
segmentInfo.startOffset = segmentStartOffset;
segmentInfo.endOffset = segmentEndOffset;
segmentInfo.duration = segmentDuration;
segmentInfo.text = state.fixedText;  // 最终确认的文本
segmentInfo.speakerId = speakerId;
segmentInfo.ossStartPosition = ossStartPosition;
segmentInfo.ossEndPosition = ossEndPosition;
state.segments.add(segmentInfo);  // 添加到段列表

// 7. 更新总有效音频时长
state.totalValidAudioDuration += segmentDuration;

// 8. 发布段完成消息到Redis
publishSegmentComplete(state.meetingId, segmentInfo);

// 9. 发送段完成消息给客户端
sendSegmentCompleteResponse(session, segmentInfo);

// 10. 重置当前段，准备下一段
state.currentSegmentAudio.clear();
state.asrVid = String.valueOf(snowflake.nextId());  // 新的ASR会话ID
state.asrPackageIndex.set(0);  // 重置包索引
state.fixedText = "";
state.tmpText = "";

// 11. 重置VAD flag，等待下一段的有效语音
String vid = vidMap.get(session.getId());
if (vid != null) {
    vadFlagMap.put(vid, true);
}
```

### 阶段6：声纹识别与向量匹配

#### 6.1 调用声纹识别API
**方法**: `performVoiceprintRecognition(String meetingId, byte[] audioData)`

```java
// 1. 构建声纹识别请求
VoiceprintRequest request = new VoiceprintRequest();
request.setVid(String.valueOf(snowflake.nextId()));  // 声纹会话ID
request.setAudioLength(audioData.length);  // 音频长度（字节）
request.setAudio(java.util.Base64.getEncoder().encodeToString(audioData));  // Base64编码的音频

// 2. 调用声纹识别API
VoiceprintResponse response = voiceprintAPI.recognize(request);
// API: POST https://www.hojoai.com/tts/voiceprint

// 3. 检查响应
if (response == null || response.getRtn() != 0) {
    return null;  // 失败不影响主流程
}

// 4. 解析声纹向量（192维）
double[] voiceprint = response.getVoiceprint();
// 返回格式：{"msg": "voiceprint success!", "rtn": 0, "vid": "...", "voiceprint": "[0.277, 1.037, ...]"}
```

#### 6.2 向量匹配
```java
// 1. 在PostgreSQL中匹配说话人
String matchedSpeakerId = voiceprintVectorService.matchSpeaker(meetingId, voiceprint, voiceprintThreshold);
// threshold = 0.85（可配置）

// 匹配逻辑（SQL）：
// SELECT speaker_id, 1 - (voiceprint <=> $1::vector) as similarity
// FROM meeting_voiceprints
// WHERE meeting_id = $2
// ORDER BY voiceprint <=> $1::vector
// LIMIT 1
// 如果 similarity >= 0.85，返回匹配的speakerId

// 2. 如果匹配成功
if (matchedSpeakerId != null) {
    return matchedSpeakerId;  // 使用已有的说话人ID
}

// 3. 如果未匹配，创建新的说话人
String newSpeakerId = "speaker-" + snowflake.nextId();
voiceprintVectorService.saveVoiceprint(meetingId, newSpeakerId, voiceprint);
// 保存到PostgreSQL：INSERT INTO meeting_voiceprints (meeting_id, speaker_id, voiceprint, ...)

return newSpeakerId;
```

## 三、关键数据结构

### SessionState（会话状态）
```java
private static class SessionState {
    String meetingId;              // 会议ID
    long meetingStartTime;         // 会议开始时间
    boolean recording = true;      // 录制状态
    
    // ASR相关
    String asrVid;                 // ASR会话ID
    AtomicInteger asrPackageIndex; // ASR包索引
    String fixedText = "";         // 已确认文本
    String tmpText = "";           // 临时文本
    
    // OSS相关
    String ossPcmObjectKey;        // OSS中PCM文件的key
    long ossCurrentPosition;       // OSS中的当前位置
    
    // 音频段管理
    long totalValidAudioDuration;  // 累积的有效音频时长（毫秒）
    List<AudioSegmentInfo> segments;  // 所有音频段信息
    String currentSegmentId;       // 当前段ID
    long currentSegmentStartOffset; // 当前段在总时间轴的起始位置
    List<byte[]> currentSegmentAudio; // 当前段的音频包列表

```


## 四、时间轴计算说明

### 时间轴特点
- **只计算有效音频时长**：只有通过VAD检测的音频才计入时间轴
- **累积计算**：每段音频的时长累加到总时长中
- **段位置计算**：
  - `segmentStartOffset = totalValidAudioDuration`（段开始位置 = 当前总时长）
  - `segmentEndOffset = totalValidAudioDuration + segmentDuration`（段结束位置 = 当前总时长 + 段时长）

### 示例
假设有3段音频：
- 段1：2000ms（0ms - 2000ms）
- 段2：3000ms（2000ms - 5000ms）
- 段3：1500ms（5000ms - 6500ms）

总有效音频时长：6500ms

## 五、OSS存储说明

### PCM文件追加
- **路径**: `meeting/{meetingId}/audio.pcm`
- **方式**: 使用OSS AppendObject，每段完成后实时追加
- **位置追踪**: 使用`ossCurrentPosition`记录当前位置

### 会议结束时转换
- **下载完整PCM**: `ossUtil.downloadObject(ossPcmObjectKey)`
- **PCM转WAV**: `audioConverter.convertPcmToWav(pcmFile, wavFile)`
- **上传WAV**: `ossUtil.uploadFile("meeting/{meetingId}/audio.wav", wavFile)`

## 六、异常处理

### 声纹识别失败
- 不影响主流程，返回`null`作为speakerId
- 记录警告日志

### OSS追加失败
- 记录错误日志
- 文件保留在OSS中，便于后续恢复

### ASR识别失败
- 记录错误日志
- 不影响后续音频包的处理

## 七、流程总结

1. **连接建立** → 生成meetingId → 下发客户端
2. **接收音频** → Base64解码 → 累积缓冲区
3. **VAD检测** → 累计评分达到阈值 → 开始ASR
4. **ASR识别** → 实时返回文本（fixedText + tmpText）→ isEnd=1触发段完成
5. **段完成处理** → 合并音频 → OSS追加 → 声纹识别 → 向量匹配 → Redis发布
6. **准备下一段** → 重置状态 → 等待新的有效语音

整个过程是**流式处理**，音频数据实时处理，每段完成后立即进行后续操作。
