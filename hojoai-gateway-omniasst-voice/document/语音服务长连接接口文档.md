# 语音服务长连接接口文档

## 一、概述

本文档描述语音服务的所有 WebSocket 长连接接口协议，包含翻译场景、会议场景和TTS场景等。

### 连接方式
- **翻译场景**: `ws://host:port/omniasst-voice/translate`
- **会议场景**: `ws://host:port/omniasst-voice/meeting`
- **TTS场景**: `ws://host:port/omniasst-voice/common/tts`

### 连接建立
建立连接时，可以通过以下两种方式传递设备ID和用户ID：

**方式1：请求头（推荐，适用于非浏览器客户端）**
```
X-Device-Id: device123 (可选)
X-User-Id: user456 (可选)
```

**方式2：URL查询参数（适用于浏览器客户端）**
由于浏览器限制，WebSocket连接无法自定义请求头，可通过URL查询参数传递：
```
ws://host:port/omniasst-voice/translate?deviceId=device123&userId=user456
ws://host:port/omniasst-voice/meeting?deviceId=device123&userId=user456
ws://host:port/omniasst-voice/common/tts?deviceId=device123&userId=user456
```

**优先级**：服务端优先从请求头获取，如果请求头中没有，则从URL查询参数中获取。

### 心跳机制
- **心跳间隔**: 10秒（客户端主动发送）
- **超时时间**: 30秒（连续3轮无心跳则断开连接）
- **心跳消息**: 见下方心跳消息格式

## 二、翻译场景 (`/omniasst-voice/translate`)

### 2.1 连接特性
- **消息类型**: 仅支持文本消息（JSON格式）
- **文本消息**: 配置、心跳、音频数据（Base64编码）、识别结果

### 2.2 消息格式

#### 2.2.1 统一消息格式
所有文本消息采用统一格式：
```json
{
  "event": "事件类型",
  "payload": {
    "pdata": {
      // 具体业务数据
    }
  }
}
```

### 2.3 流程说明

#### 流程1: 配置阶段
连接建立后，客户端必须先发送配置消息。

**客户端发送配置消息**:
```json
{
  "event": "REQ_ASR_TRANSLATE_CONFIG",
  "payload": {
    "pdata": {
      "sourceLanguage": "chinese",
      "targetLanguage": "english",
      "extendAttr": {
        "conversationId": "conv-123456"
      }
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| sourceLanguage | String | 是 | 源语言：chinese、english、french |
| targetLanguage | String | 是 | 目标语言：chinese、english、french |
| extendAttr | Object | 否 | 扩展属性 |
| extendAttr.conversationId | String | 否 | 对话ID（PA对话页面进入会携带） |

**注意**: 
- `ttsLanguage` 和 `ttsVoiceId` 不需要配置，服务端会根据翻译的目标语言自动选择
- 如果用户说中文翻译成英文，TTS会自动使用英文语音
- 如果用户说英文翻译成中文，TTS会自动使用中文语音

**服务端返回ChatId**:
```json
{
  "event": "BACK_CHAT_ID",
  "payload": {
    "pdata": {
      "chatId": "chatId-1234567890123456789"
    }
  }
}
```

#### 流程2: 音频处理阶段
配置完成后，客户端开始发送音频数据。

**客户端发送音频数据**（文本消息，Base64编码）:
```json
{
  "event": "REQ_TRANSLATE_AUDIO_DATA",
  "payload": {
    "pdata": {
      "audioData": "UklGRiQAAABXQVZFZm10..."
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| audioData | String | 是 | Base64编码的PCM音频数据 |

**音频格式要求**:
- **格式**: PCM格式，16k采样率，16bit，单声道
- **编码**: Base64编码后作为字符串传输
- **包大小**: 建议按标准包大小（10240字节 = 320ms的音频）发送，服务端会累积到该大小后处理

**服务端处理流程**:
1. **VAD判断**: 累积到10240字节后调用VAD，判断音频有效性
2. **ASR识别**: VAD判断有效后，开始ASR识别
3. **语种检测**: ASR识别过程中，检测当前语种（lang_detect）
4. **翻译处理**: 
   - 检测到语种后，判断是sourceLanguage还是targetLanguage
   - 如果是sourceLanguage，则翻译到targetLanguage
   - 如果是targetLanguage，则翻译到sourceLanguage
   - 将之前缓存的音频包一起发送给翻译接口
5. **同步调用**: 语种检测后，ASR和翻译接口同步调用
6. **TTS合成**: 翻译完成后，调用TTS接口合成音频

**服务端返回识别结果**（文本消息）:
```json
{
  "event": "BACK_ASR_TEXT",
  "payload": {
    "pdata": {
      "text": "你好，这是一段测试文本",
      "tranText": "Hello, this is a test text",
      "currLang": "chinese",
      "isEnd": 0
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| text | String | ASR识别后的文本（全量，每次都是完整文本） |
| tranText | String | 翻译后的文本（为空表示翻译还未开始或还未返回） |
| currLang | String | 当前检测到的语种：chinese、english、french |
| isEnd | Integer | 0=未结束，1=结束 |

**服务端返回TTS音频流**（文本消息，Base64编码）:
```json
{
  "event": "BACK_TRANS_TTS_AUDIO",
  "payload": {
    "pdata": {
      "chatId": "chatId-1234567890123456789",
      "audioData": "UklGRiQAAABXQVZFZm10..."
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| chatId | String | 对话ID（与配置时返回的chatId一致） |
| audioData | String | Base64编码的PCM音频数据 |

**音频格式说明**:
- **音频格式**: PCM格式，16k采样率，16bit，单声道
- **编码方式**: Base64编码后作为字符串传输
- **推送方式**: 流式推送，服务端接收到TTS响应后立即Base64编码并推送
- **客户端处理**: 客户端需要Base64解码后播放，可以边收边播放（流式播放）
- **OSS存储**: TTS音频流推送完成后会保存到OSS

**错误消息**:
```json
{
  "event": "BACK_ERROR",
  "payload": {
    "pdata": {
      "errorCode": "错误代码",
      "errorMessage": "错误信息",
      "stage": "错误阶段（config/asr/translate/tts/process）"
    }
  }
}
```

**错误代码**:
- `CONFIG_ERROR`: 配置错误
- `ASR_ERROR`: ASR识别错误
- `TRANSLATE_ERROR`: 翻译服务错误
- `TTS_ERROR`: TTS合成错误
- `PROCESS_ERROR`: 处理过程错误
- `GENERAL_ERROR`: 通用错误
- `ILLEGAL_ARGUMENT`: 参数错误
- `UNSUPPORTED_OPERATION`: 不支持的操作

#### 流程3: 心跳消息

**客户端发送心跳**（每10秒）:
```json
{
  "event": "REQ_HEARTBEAT",
  "payload": {
    "pdata": {
      "timestamp": 1234567890
    }
  }
}
```

**服务端响应心跳**:
```json
{
  "event": "BACK_HEARTBEAT",
  "payload": {
    "pdata": {
      "timestamp": 1234567890,
      "serverTime": 1234567891
    }
  }
}
```

#### 流程4: 关闭连接

**客户端主动断开连接**:
```json
{
  "event": "REQ_TRANSLATE_STOP",
  "payload": {
    "pdata": {}
  }
}
```

**服务端响应**:
```json
{
  "event": "BACK_TRANSLATE_STOP_ACK",
  "payload": {
    "pdata": {
      "status": "success",
      "chatId": "chatId-1234567890123456789",
      "message": "Translation stopped successfully"
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| status | String | 状态：success（客户端主动停止）、complete（ASR自然结束） |
| chatId | String | 对话ID |
| message | String | 消息描述 |

**注意**:
- 客户端发送 `REQ_TRANSLATE_STOP` 后，服务端会先发布最后一次翻译结果（isEnd=0），然后发布一条空数据（isEnd=1），最后发送确认消息
- 服务端不会主动关闭连接，连接由客户端关闭
- 当ASR自然结束（isEnd=1）时，服务端会发送 `BACK_TRANSLATE_STOP_ACK`（status="complete"），表示翻译完成

## 三、会议场景 (`/omniasst-voice/meeting`)

### 3.1 连接特性
- **消息类型**: 仅支持文本消息（JSON格式）
- **功能**: VAD + ASR识别 + 声纹识别
- **不支持**: 翻译和TTS

### 3.2 消息格式

#### 3.2.1 统一消息格式
所有文本消息采用统一格式：
```json
{
  "event": "事件类型",
  "payload": {
    "pdata": {
      // 具体业务数据
    }
  }
}
```

#### 3.2.2 音频数据（文本消息，Base64编码）
```json
{
  "event": "REQ_MEETING_AUDIO_DATA",
  "payload": {
    "pdata": {
      "audioData": "UklGRiQAAABXQVZFZm10..."
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| audioData | String | 是 | Base64编码的PCM音频数据 |

**音频格式要求**:
- **格式**: PCM格式，16k采样率，16bit，单声道
- **编码**: Base64编码后作为字符串传输
- **包大小**: 建议按标准包大小（10240字节 = 320ms的音频）发送，服务端会累积到该大小后处理

### 3.3 流程说明

#### 流程1: 连接建立与初始化
连接建立后，服务端会立即下发会议ID。

**服务端返回会议ID**:
```json
{
  "event": "BACK_MEETING_ID",
  "payload": {
    "pdata": {
      "meetingId": "meeting-1234567890123456789",
      "timestamp": 1704067200000
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| meetingId | String | 唯一会议标识（格式：meeting-{雪花ID}） |
| timestamp | Long | 会议开始时间戳（毫秒） |

#### 流程2: 音频处理阶段
收到会议ID后，客户端开始发送音频数据。

**客户端发送音频数据**（文本消息，Base64编码）:
```json
{
  "event": "REQ_MEETING_AUDIO_DATA",
  "payload": {
    "pdata": {
      "audioData": "UklGRiQAAABXQVZFZm10..."
    }
  }
}
```

**服务端处理流程**:
1. **VAD判断**: 累积到10240字节后调用VAD，判断音频有效性
2. **ASR识别**: VAD判断有效后，开始ASR识别
3. **返回识别结果**: 实时返回ASR识别文本

**服务端返回识别结果**（文本消息）:
```json
{
  "event": "BACK_MEETING_ASR_TEXT",
  "payload": {
    "pdata": {
      "fixedText": "你好，这是一段",
      "tmpText": "测试",
      "isEnd": 0,
      "segmentId": "1234567890123456789",
      "segmentStartTime": "00:05"
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| fixedText | String | 已确认的文本（稳定部分） |
| tmpText | String | 临时文本（正在识别的部分，可能变化） |
| isEnd | Integer | 0=未结束（继续识别），1=结束（当前段完成） |
| segmentId | String | 当前音频段的ID |
| segmentStartTime | String | 段开始时间，格式"MM:SS"，相对于会议开始的时间（包含静音时间） |

**服务端返回段完成通知**（当isEnd=1时）:
```json
{
  "event": "BACK_MEETING_SEGMENT_COMPLETE",
  "payload": {
    "pdata": {
      "segmentId": "segment-1234567890123456789",
      "text": "你好，这是一段测试文本",
      "speakerId": "user-123",
      "speakerName": "张三",
      "speakerAvatar": "https://example.com/avatar.jpg",
      "startTime": 0,
      "endTime": 5000,
      "segmentStartTime": "00:05",
      "timestamp": 1704067200000
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| segmentId | String | 音频段唯一标识 |
| text | String | 该段的完整识别文本 |
| speakerId | String | 说话人ID（通过声纹识别匹配，可能是用户ID或会议内编号） |
| speakerName | String | 说话人名称（匹配到用户时返回用户名，会议内编号时返回"发言人-1"格式） |
| speakerAvatar | String | 说话人头像URL（匹配到用户时返回头像，为空时返回空字符串） |
| startTime | Long | 段在总时间轴的起始位置（毫秒，基于有效音频时长） |
| endTime | Long | 段在总时间轴的结束位置（毫秒，基于有效音频时长） |
| segmentStartTime | String | 段开始时间，格式"MM:SS"，相对于会议开始的时间（包含静音时间） |
| timestamp | Long | 消息发送时间戳（毫秒） |

**错误消息**:
```json
{
  "event": "BACK_ERROR",
  "payload": {
    "pdata": {
      "errorCode": "错误代码",
      "errorMessage": "错误信息",
      "stage": "错误阶段（asr/process）"
    }
  }
}
```

**错误代码**:
- `ASR_ERROR`: ASR识别错误
- `PROCESS_ERROR`: 处理过程错误
- `GENERAL_ERROR`: 通用错误
- `ILLEGAL_ARGUMENT`: 参数错误

#### 流程3: 心跳机制
会议场景支持心跳机制，通过文本消息更新活跃时间。

**客户端发送心跳**（每10秒，文本消息）:
```json
{
  "event": "REQ_HEARTBEAT",
  "payload": {
    "pdata": {
      "timestamp": 1234567890
    }
  }
}
```

**服务端响应心跳**:
```json
{
  "event": "BACK_HEARTBEAT",
  "payload": {
    "pdata": {
      "timestamp": 1234567890,
      "serverTime": 1234567891
    }
  }

```

**注意**: 收到任何消息（文本心跳、二进制音频）都会更新最后活跃时间。

#### 流程4: 关闭连接

**客户端主动断开连接**:
```json
{
  "event": "REQ_MEETING_STOP",
  "payload": {
    "pdata": {
      "needSave": 1
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| needSave | Integer | 是 | 是否需要保存：0=不保存，1=保存 |

**服务端响应**:
```json
{
  "event": "BACK_MEETING_STOP_ACK",
  "payload": {
    "pdata": {
      "status": "success",
      "meetingId": "meeting-1234567890123456789",
      "totalDuration": 120000,
      "segmentCount": 5,
      "message": "Meeting stopped successfully"
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| status | String | 状态：success（成功） |
| meetingId | String | 会议ID |
| totalDuration | Long | 总有效音频时长（毫秒） |
| segmentCount | Integer | 音频段总数 |
| message | String | 消息描述 |

**注意**:
- 客户端发送 `REQ_MEETING_STOP` 后，服务端会先完成当前正在处理的音频段，然后处理会议结束（下载完整音频、转换为WAV、上传OSS、发布最终结果到Redis），最后发送确认消息
- 服务端不会主动关闭连接，连接由客户端关闭
- 如果心跳超时（超过30秒无心跳）或应用异常关闭，服务端会默认保存（needSave=1）

## 四、TTS场景 (`/omniasst-voice/common/tts`)

### 4.1 连接特性
- **消息类型**: 文本消息（JSON格式）和二进制消息（音频流）
- **功能**: 文本转语音，通过WebSocket通道流式输出音频
- **支持**: 文本消息请求、文本消息响应（标志报文）、二进制消息（音频流）
- **文本流式输入**: 支持分块发送文本，最后一个文本块标记完成
- **串行处理**: 服务端会暂存文本，串行执行TTS请求，避免并发

### 4.2 消息格式

#### 4.2.1 统一消息格式
所有文本消息采用统一格式：
```json
{
  "event": "事件类型",
  "payload": {
    "pdata": {
      // 具体业务数据
    }
  }
}
```

### 4.3 流程说明

#### 流程1: 连接建立
连接建立后，客户端可以立即发送TTS请求。

#### 流程2: TTS请求与响应

**客户端发送TTS请求**（文本消息，支持流式输入）:
```json
{
  "event": "REQ_TTS_TEXT",
  "payload": {
    "pdata": {
      "text": "你好，这是一段",
      "isEnd": 0
    }
  }
}
```

```json
{
  "event": "REQ_TTS_TEXT",
  "payload": {
    "pdata": {
      "text": "测试文本",
      "isEnd": 1
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| text | String | 是 | 需要转换为语音的文本内容（支持分块发送） |
| isEnd | Integer | 是 | 是否最后一块文本：0=未完成，1=完成 |

**注意事项**:
- 文本可以分多次发送，每次发送一个文本块
- 最后一个文本块必须设置 `isEnd=1`，表示文本输入完成
- 服务端会暂存文本块，当当前TTS请求完成后，将暂存的文本合并后统一进行TTS合成
- 如果客户端快速发送多个文本块，后续的文本块会被暂存，等待前一个TTS请求完成后再处理
- 服务端固定使用中文（chinese）和中文音色进行TTS合成，不需要传递语言参数

**服务端返回TTS开始标志**（文本消息）:
```json
{
  "event": "BACK_COMMON_TTS_FLAG",
  "payload": {
    "pdata": {
      "finishFlag": "START"
    }
  }
}
```

**服务端返回音频流**（二进制消息）:
服务端通过二进制消息流式推送PCM音频数据，每个音频块都是独立的二进制消息。

**服务端返回TTS结束标志**（文本消息，仅在收到isEnd=1的文本且TTS处理完成后发送）:
```json
{
  "event": "BACK_COMMON_TTS_FLAG",
  "payload": {
    "pdata": {
      "finishFlag": "FINISH"
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 说明 |
|--------|------|------|
| finishFlag | String | TTS标志：START（开始）、FINISH（结束） |

**音频格式说明**:
- **音频格式**: PCM格式，16k采样率，16bit，单声道
- **推送方式**: 二进制消息，直接推送原始PCM音频数据
- **流式推送**: 服务端接收到TTS响应后，立即以二进制消息推送音频数据
- **客户端处理**: 客户端直接接收二进制音频数据，可以边收边播放（流式播放）
- **标志报文**: 
  - START：每次开始TTS处理时发送（文本消息）
  - FINISH：只有在收到isEnd=1的文本且TTS处理完成后才发送（文本消息）

**错误消息**（文本消息）:
```json
{
  "event": "BACK_ERROR",
  "payload": {
    "pdata": {
      "errorCode": "错误代码",
      "errorMessage": "错误信息",
      "stage": "tts"
    }
  }

```

**错误代码**:

- `GENERAL_ERROR`: 通用错误（如TTS服务调用失败）
- `UNSUPPORTED_OPERATION`: 不支持的操作

**服务端响应心跳**:
```json

  "event": "BACK_HEARTBEAT",
  "payload": {
    "pdata": {
      "timestamp": 1234567890,
      "serverTime": 1234567891
    }
  }
}
```

**注意**: 收到任何消息（心跳、TTS请求）都会更新最后活跃时间。

#### 流程4: 关闭连接

**客户端主动断开连接**:
- 客户端可以直接关闭WebSocket连接
- 服务端不会主动关闭连接，只有在心跳超时时会关闭连接

**注意事项**:
- 心跳间隔：10秒（客户端主动发送）
- 超时时间：30秒（连续3轮无心跳则断开连接）
- 服务端不会主动关闭连接，只有在心跳超时时会关闭连接
- 浏览器客户端无法自定义请求头，必须通过URL查询参数传递deviceId和userId

## 六、注意事项

### 6.1 翻译场景
1. **配置必须**: 连接建立后必须先发送配置消息，否则无法处理音频
2. **语种检测**: ASR识别过程中会自动检测语种，检测到语种后才会开始翻译
3. **音频缓存**: 从开始到检测到语种的音频包会被缓存，然后一起发送给翻译接口
4. **同步调用**: 语种检测后，ASR和翻译接口会同步调用
5. **TTS时机**: 翻译完成后才会调用TTS，识别过程中不会调用
6. **TTS音频格式**: 
   - 事件类型：`BACK_TRANS_TTS_AUDIO`
   - 响应格式：文本消息，包含 `chatId` 和 `audioData`（Base64编码的PCM音频数据）
   - 音频格式：PCM，16kHz，16bit，单声道
   - 编码方式：Base64编码后作为字符串传输
   - 推送方式：流式推送，服务端接收到TTS响应后立即Base64编码并推送
   - 客户端处理：需要Base64解码后播放，可以边收边播放（流式播放）
7. **OSS存储**: TTS音频流推送完成后会保存到OSS

### 6.2 会议场景
1. **无需配置**: 连接建立后可直接发送音频数据
2. **仅ASR**: 只做VAD和ASR识别，不做翻译和TTS
3. **心跳机制**: 通过文本消息更新活跃时间

### 6.3 TTS场景
1. **直接请求**: 连接建立后可直接发送TTS请求，无需配置
2. **文本流式输入**: 支持分块发送文本，最后一个文本块必须设置 `isEnd=1`
3. **文本暂存机制**: 
   - 如果当前有TTS请求正在进行，后续发送的文本块会被暂存
   - 当当前TTS请求完成后，服务端会将暂存的文本合并后统一进行TTS合成
   - 这样可以避免并发请求，减少服务器压力
4. **音频流格式**: 服务端通过二进制消息流式推送PCM音频数据
5. **音频处理**: 
   - 客户端直接接收二进制音频数据，无需解码
   - 可以边收边播放（流式播放），也可以累积完整后播放
6. **标志报文**: 
   - START：每次开始TTS处理时发送（文本消息）
   - FINISH：只有在收到isEnd=1的文本且TTS处理完成后才发送（文本消息）
   - 标志报文用于标识TTS处理的开始和结束，便于客户端控制播放状态
7. **语言和音色**: 服务端固定使用中文（chinese）和中文音色，不需要客户端指定
8. **心跳机制**: 支持心跳机制保持连接活跃
9. **串行处理**: TTS请求会串行执行，同一时间只有一个TTS请求在进行

### 6.4 通用注意事项
1. **心跳机制**: 客户端必须每10秒发送一次心跳，超过30秒无心跳会被断开
2. **活跃时间**: 收到任何消息（心跳、音频、文本）都会更新最后活跃时间
3. **错误处理**: 收到错误消息后，客户端应根据错误代码和阶段进行相应处理
4. **连接关闭**: 服务端不会主动关闭连接，只有在以下两种情况下会关闭：
   - **心跳超时**: 超过30秒无心跳，服务端主动关闭连接
   - **客户端主动断开**: 客户端发送停止请求后，由客户端关闭连接
5. **浏览器兼容**: 浏览器客户端无法自定义请求头，必须通过URL查询参数传递deviceId和userId

## 八、错误处理

### 7.1 常见错误场景

1. **配置错误**
   - 未发送配置直接发送音频
   - 配置参数缺失或格式错误
   - 返回: `CONFIG_ERROR`

2. **ASR错误**
   - ASR服务调用失败
   - 音频格式不正确
   - 返回: `ASR_ERROR`

3. **翻译错误**
   - 翻译服务调用失败
   - 语种检测失败
   - 返回: `TRANSLATE_ERROR`

4. **TTS错误**
   - TTS服务调用失败
   - 音频合成失败
   - 参数错误（如text为空）
   - 返回: `TTS_ERROR` 或 `ILLEGAL_ARGUMENT` 或 `GENERAL_ERROR`

5. **超时错误**
   - 超过30秒无心跳
   - 服务端主动关闭连接
   - 关闭状态: `SESSION_NOT_RELIABLE`

6. **连接关闭**
   - 客户端主动发送停止请求（`REQ_MEETING_STOP` 或 `REQ_TRANSLATE_STOP`）
   - 服务端响应确认消息后，由客户端关闭连接
   - 心跳超时后，服务端主动关闭连接

### 7.2 错误处理建议

1. **重试机制**: 对于临时性错误（如网络抖动），建议实现重试机制
2. **日志记录**: 记录所有错误信息，便于问题排查
3. **用户提示**: 根据错误类型给用户适当的提示
4. **连接恢复**: 连接断开后，应支持自动重连
