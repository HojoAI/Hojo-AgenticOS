# 端侧音频上传协议说明

本文档说明翻译场景和会议场景中，端侧如何通过WebSocket上传音频数据。

## 一、通用说明

### 1.1 消息格式

所有消息均为**文本消息（TextMessage）**，采用JSON格式：

```json
{
  "event": "事件类型",
  "payload": {
    "pdata": {
      // 具体业务数据
    }
  }
}
```

### 1.2 音频数据格式要求

- **原始格式**: PCM格式，16k采样率，16bit，单声道
- **传输格式**: Base64编码后的字符串
- **建议包大小**: 10240字节（约320ms的音频）发送一次，服务端会累积到该大小后处理

### 1.3 Base64编码示例

```javascript
// JavaScript示例
const audioBuffer = new Uint8Array([...]); // PCM音频数据
const base64Audio = btoa(String.fromCharCode(...audioBuffer));
// 或使用
const base64Audio = Buffer.from(audioBuffer).toString('base64');
```

## 二、翻译场景（`/omniasst-voice/translate`）

### 2.1 完整流程

```
1. 建立WebSocket连接
   ↓
2. 发送配置消息（REQ_ASR_TRANSLATE_CONFIG）
   ↓
3. 接收chatId（BACK_CHAT_ID）
   ↓
4. 持续发送音频数据（REQ_TRANSLATE_AUDIO_DATA）
   ↓
5. 接收识别结果（BACK_ASR_TEXT）
   ↓
6. 接收TTS音频流（二进制数据）
   ↓
7. 发送停止消息（REQ_TRANSLATE_STOP）
   ↓
8. 关闭连接
```

### 2.2 音频数据上传

**事件类型**: `REQ_TRANSLATE_AUDIO_DATA`

**请求格式**:
```json
{
  "event": "REQ_TRANSLATE_AUDIO_DATA",
  "payload": {
    "pdata": {
      "audioData": "UklGRiQAAABXQVZFZm10..."
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| audioData | String | 是 | Base64编码的PCM音频数据 |

**注意事项**:
- 必须先发送配置消息（`REQ_ASR_TRANSLATE_CONFIG`）并收到 `chatId` 后才能发送音频数据
- 音频数据需要持续发送，直到识别完成或主动停止
- 服务端会累积音频数据，达到10240字节后开始处理

## 三、会议场景（`/omniasst-voice/meeting`）

### 3.1 完整流程

```
1. 建立WebSocket连接
   ↓
2. 接收meetingId（BACK_MEETING_ID）
   ↓
3. 持续发送音频数据（REQ_MEETING_AUDIO_DATA）
   ↓
4. 接收识别结果（BACK_MEETING_ASR_TEXT）
   ↓
5. 接收段完成通知（BACK_MEETING_SEGMENT_COMPLETE）
   ↓
6. 发送停止消息（REQ_MEETING_STOP）
   ↓
7. 接收停止确认（BACK_MEETING_STOP_ACK）
   ↓
8. 关闭连接
```

### 3.2 音频数据上传

**事件类型**: `REQ_MEETING_AUDIO_DATA`

**请求格式**:
```json
{
  "event": "REQ_MEETING_AUDIO_DATA",
  "payload": {
    "pdata": {
      "audioData": "UklGRiQAAABXQVZFZm10..."
    }
  }
}
```

**参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| audioData | String | 是 | Base64编码的PCM音频数据 |

**注意事项**:
- 连接建立后，服务端会自动下发 `meetingId`，无需客户端先发送配置
- 音频数据需要持续发送，直到会议结束
- 服务端会累积音频数据，达到10240字节后开始VAD检测和ASR识别

## 四、完整示例

### 4.1 翻译场景示例（JavaScript）

```javascript
// 1. 建立连接
const ws = new WebSocket('ws://localhost:12002/omniasst-voice/translate?deviceId=device123&userId=user456');

// 2. 连接建立后，发送配置
ws.onopen = () => {
  const configMsg = {
    event: 'REQ_ASR_TRANSLATE_CONFIG',
    payload: {
      pdata: {
        sourceLanguage: 'chinese',
        targetLanguage: 'english'
      }
    }
  };
  ws.send(JSON.stringify(configMsg));
};

// 3. 接收消息
ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  
  if (msg.event === 'BACK_CHAT_ID') {
    const chatId = msg.payload.pdata.chatId;
    console.log('ChatId:', chatId);
    
    // 开始发送音频数据
    startSendingAudio(ws);
  } else if (msg.event === 'BACK_ASR_TEXT') {
    const text = msg.payload.pdata.text;
    const transText = msg.payload.pdata.tranText;
    console.log('识别:', text);
    console.log('翻译:', transText);
  } else if (event.data instanceof Blob) {
    // TTS音频流（二进制数据）
    const audioBlob = event.data;
    // 处理音频...
  }
};

// 4. 发送音频数据
function startSendingAudio(ws) {
  // 假设有一个音频采集器，每320ms采集一次
  setInterval(() => {
    const pcmData = getPCMAudioData(); // 获取PCM数据（Uint8Array）
    const base64Audio = arrayBufferToBase64(pcmData);
    
    const audioMsg = {
      event: 'REQ_TRANSLATE_AUDIO_DATA',
      payload: {
        pdata: {
          audioData: base64Audio
        }
      }
    };
    ws.send(JSON.stringify(audioMsg));
  }, 320);
}

// Base64编码工具函数
function arrayBufferToBase64(buffer) {
  const bytes = new Uint8Array(buffer);
  let binary = '';
  for (let i = 0; i < bytes.byteLength; i++) {
    binary += String.fromCharCode(bytes[i]);
  }
  return btoa(binary);
  // 或使用：return Buffer.from(bytes).toString('base64'); // Node.js环境
}
```

### 4.2 会议场景示例（JavaScript）

```javascript
// 1. 建立连接
const ws = new WebSocket('ws://localhost:12002/omniasst-voice/meeting?deviceId=device123');

// 2. 接收meetingId
ws.onopen = () => {
  console.log('连接已建立');
};

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  
  if (msg.event === 'BACK_MEETING_ID') {
    const meetingId = msg.payload.pdata.meetingId;
    console.log('MeetingId:', meetingId);
    
    // 开始发送音频数据
    startSendingAudio(ws);
  } else if (msg.event === 'BACK_MEETING_ASR_TEXT') {
    const text = msg.payload.pdata.text;
    console.log('识别:', text);
  } else if (msg.event === 'BACK_MEETING_SEGMENT_COMPLETE') {
    const segment = msg.payload.pdata;
    console.log('段完成:', segment);
  }
};

// 3. 发送音频数据（与翻译场景相同）
function startSendingAudio(ws) {
  setInterval(() => {
    const pcmData = getPCMAudioData();
    const base64Audio = arrayBufferToBase64(pcmData);
    
    const audioMsg = {
      event: 'REQ_MEETING_AUDIO_DATA',
      payload: {
        pdata: {
          audioData: base64Audio
        }
      }
    };
    ws.send(JSON.stringify(audioMsg));
  }, 320);
}
```

## 五、常见问题

### Q1: 音频数据需要多长时间发送一次？

**A**: 建议每320ms（约10240字节）发送一次，服务端会累积到该大小后处理。也可以更频繁地发送，服务端会自动累积。

### Q2: Base64编码会增加数据大小吗？

**A**: 是的，Base64编码会使数据大小增加约33%（从二进制变为文本）。但考虑到WebSocket对文本消息的良好支持，这是可以接受的。

### Q3: 如果发送的音频数据小于10240字节会怎么样？

**A**: 服务端会将数据累积到缓冲区，当累积到10240字节时开始处理。如果是最后一段音频（小于10240字节），会在识别结束时（isEnd=1）一起处理。

### Q4: 可以一次性发送很长的音频数据吗？

**A**: 可以，但不建议。建议按照320ms的音频包大小发送，这样可以更好地控制延迟和处理效率。

## 六、错误处理

如果发送的音频数据格式不正确，服务端会返回错误消息：

```json
{
  "event": "BACK_ERROR",
  "payload": {
    "pdata": {
      "errorCode": "ILLEGAL_ARGUMENT",
      "errorMessage": "Invalid Base64 audio data",
      "stage": "process"
    }
  }
}
```

常见错误：
- `ILLEGAL_ARGUMENT`: 音频数据为空或Base64格式不正确
- `CONFIG_ERROR`: 配置未找到（翻译场景需要先发送配置）
- `PROCESS_ERROR`: 处理过程错误
